5. Transactions, isolation et verrouillage

Une transaction regroupe des opérations qui doivent réussir ou échouer ensemble. Avec node-postgres, toutes les instructions d'une transaction doivent utiliser le même client, pas des appels indépendants au pool.

import type { Pool, PoolClient } from "pg";

export async function transfer(
  pool: Pool,
  fromId: string,
  toId: string,
  amount: number,
): Promise<void> {
  if (!Number.isSafeInteger(amount) || amount <= 0) {
    throw new Error("amount must be a positive safe integer");
  }

  const client: PoolClient = await pool.connect();
  try {
    await client.query("BEGIN");
    const debit = await client.query(
      `UPDATE accounts
       SET balance_cents = balance_cents - $1
       WHERE id = $2 AND balance_cents >= $1
       RETURNING id`,
      [amount, fromId],
    );
    if (debit.rowCount !== 1) throw new Error("Insufficient funds or account missing");

    const credit = await client.query(
      "UPDATE accounts SET balance_cents = balance_cents + $1 WHERE id = $2 RETURNING id",
      [amount, toId],
    );
    if (credit.rowCount !== 1) throw new Error("Destination account missing");
    await client.query("COMMIT");
  } catch (error) {
    try { await client.query("ROLLBACK"); } catch { /* préserver l'erreur initiale */ }
    throw error;
  } finally {
    client.release();
  }
}

Cet extrait illustre la structure, mais ne suffit pas à rendre un transfert complet en production : il faut notamment valider l'existence et la différence des comptes, définir les règles de devise, gérer les deadlocks et les erreurs de sérialisation, prévoir l'idempotence au niveau métier et tester les écritures concurrentes. En production, ne pas relancer aveuglément une opération dont l'issue est incertaine après une coupure réseau.

  • READ COMMITTED : chaque instruction voit un nouvel instantané ; deux lectures dans une transaction peuvent donc différer.
  • REPEATABLE READ : cohérence de l'instantané transactionnel, avec des conflits possibles.
  • SERIALIZABLE : vise l'équivalence à une exécution séquentielle, mais peut annuler une transaction ; l'application doit prévoir une reprise bornée et sûre.
  • Verrouillage (SELECT ... FOR UPDATE) : utile pour certaines règles concurrentes, mais peut créer attente et deadlock. Toujours définir un ordre de prise de verrous et des délais adaptés.

Ne pas augmenter l'isolation par réflexe : identifier d'abord l'invariant métier et le mécanisme nécessaire.
