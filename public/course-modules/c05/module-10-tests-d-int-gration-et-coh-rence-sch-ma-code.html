10. Tests d'intégration et cohérence schéma/code

Les tests unitaires peuvent tester les règles métier avec un dépôt simulé, mais ils ne prouvent pas que SQL, contraintes, migrations, transactions ou types du pilote fonctionnent ensemble.

Une suite d'intégration utile :

  • démarre une base isolée de la même famille/version que la cible ;
  • applique toutes les migrations depuis un état vide ;
  • insère des données représentatives et vérifie les contraintes ;
  • teste les chemins de succès et d'échec d'une transaction ;
  • provoque des accès concurrents sur les invariants critiques ;
  • vérifie la pagination, les filtres et les limites de taille ;
  • détruit ou réinitialise l'environnement de test sans toucher aux données réelles.

Ne pas utiliser une base de production pour les tests. Ne pas affirmer qu'une suite a réussi si elle n'a pas été exécutée. Les tests peuvent nécessiter Docker ou un service PostgreSQL disponible ; ces prérequis doivent être explicites.
