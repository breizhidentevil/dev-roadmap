Complexité algorithmique

Estimer comment le temps et la mémoire consommés évoluent avec la taille de l’entrée, avant d’optimiser.

Tutoriel détailléLot 5 · 2026

Objectifs d’apprentissage

  • Définir la taille d’entrée et la complexité asymptotique.
  • Reconnaître O(1), O(log n), O(n), O(n log n), O(n²) et O(2ⁿ).
  • Analyser boucles, boucles imbriquées, recherches et récursions simples.
  • Mesurer sans confondre un benchmark ponctuel et une garantie théorique.

1. Que décrit Big O ?

La complexité décrit la manière dont une ressource évolue quand la taille de l’entrée n augmente. On distingue notamment le temps et la mémoire auxiliaire. La notation Big O décrit une borne asymptotique ; elle ne donne pas directement le nombre de millisecondes sur une machine particulière.

On ignore généralement les constantes et les termes de plus faible ordre : 3n² + 10n + 8 est en O(n²). Pour de petites entrées, une solution théoriquement plus coûteuse peut parfois être plus rapide en pratique à cause des constantes, de l’accès mémoire ou de l’implémentation.

2. Les ordres de grandeur usuels

ComplexitéExempleÉvolution indicative
O(1)Accès par indiceLe coût reste constant
O(log n)Recherche binaireChaque étape réduit le domaine
O(n)Parcours d’un tableauDeux fois plus d’éléments ≈ deux fois le travail
O(n log n)Tri efficace typiqueCourant pour les tris comparatifs performants
O(n²)Toutes les pairesDeux fois plus d’éléments ≈ quatre fois le travail
O(2ⁿ)Exploration exhaustive de sous-ensemblesPeut devenir impraticable rapidement

3. Lire le code

// O(n) : chaque élément est visité une fois
    function somme(tab) {
      let resultat = 0;
      for (const n of tab) resultat += n;
      return resultat;
    }
    
    // O(n²) : pour chaque élément, on reparcourt la liste
    function contientDoublonSimple(tab) {
      for (let i = 0; i < tab.length; i++) {
        for (let j = i + 1; j < tab.length; j++) {
          if (tab[i] === tab[j]) return true;
        }
      }
      return false;
    }

Deux boucles successives donnent souvent O(n) + O(n) = O(n). Deux boucles imbriquées qui parcourent toutes deux l’entrée donnent souvent O(n²). Mais il faut compter les itérations réelles : une boucle intérieure qui divise la valeur par deux n’a pas le même coût qu’une boucle qui l’incrémente de un.

4. Améliorer une recherche de doublons

function contientDoublon(tab) {
      const vus = new Set();
      for (const valeur of tab) {
        if (vus.has(valeur)) return true;
        vus.add(valeur);
      }
      return false;
    }

Cette version a un coût attendu linéaire avec une mémoire supplémentaire proportionnelle au nombre de valeurs distinctes. C’est un compromis temps/mémoire : elle échange de la mémoire contre moins de comparaisons. La complexité moyenne des opérations de Set dépend de l’implémentation et des hypothèses de hachage ; évite de présenter ces coûts comme une loi absolue de toute plateforme.

5. Récursion, espace et mesure

Une fonction récursive consomme généralement de l’espace de pile proportionnel à la profondeur des appels, sauf optimisation spécifique. Une récursion mal bornée peut provoquer un dépassement de pile. Pour analyser une récursion, précise le cas de base, le nombre d’appels et la taille de chaque sous-problème.

Pour mesurer, utilise des jeux de données de tailles croissantes, plusieurs répétitions et des conditions reproductibles. Évite d’inclure dans la mesure le chargement des données si tu veux isoler l’algorithme. Un benchmark valide complète l’analyse théorique ; il ne la remplace pas.

Erreurs fréquentes

  • Confondre Big O avec une durée exacte.
  • Oublier la mémoire consommée par une copie, une Map ou la récursion.
  • Supposer que tout sort() a une complexité garantie identique sur tous les moteurs.
  • Optimiser prématurément sans profiler.
  • Analyser seulement le cas moyen sans considérer le pire cas pertinent.

Exercice

Analyse une fonction qui cherche une valeur dans un tableau, puis une fonction qui compare chaque paire. Pour chaque fonction, indique le coût en temps et en mémoire, puis propose une version avec Set lorsque cela convient.

Critères de réussite

  • La variable n est clairement définie.
  • Les boucles et appels récursifs sont comptés correctement.
  • Le coût mémoire est distingué du coût temporel.
  • Le compromis de l’optimisation est explicité et testé.

Approfondissement — compter les opérations avant de chronométrer

Pour analyser une boucle, définis d’abord n : nombre d’éléments, longueur d’une chaîne ou nombre de sommets. Compte ensuite le nombre de fois où l’opération dominante s’exécute. L’analyse n’est valable que si tu explicites l’hypothèse sur la taille et la forme de l’entrée.

// La variable i est multipliée par 2 à chaque tour : O(log n)
for (let i = 1; i < n; i *= 2) {
  traiter(i);
}

// Le nombre de tours de la boucle interne dépend de i : O(n²)
for (let i = 0; i < n; i++) {
  for (let j = i + 1; j < n; j++) {
    comparer(i, j);
  }
}

Dans la première boucle, après k tours, i vaut environ 2^k ; atteindre n demande donc environ log₂(n) tours. Dans la seconde, le nombre de comparaisons vaut (n - 1) + (n - 2) + … + 1 = n(n - 1)/2, ce qui est quadratique. Deux boucles successives qui parcourent chacune les n éléments coûtent plutôt O(n) + O(n) = O(n), car on ignore le facteur constant dans la notation asymptotique.

O(f(n)) exprime une borne asymptotique supérieure ; on emploie souvent cette notation pour désigner l’ordre de grandeur usuel. Quand on veut préciser que la croissance est serrée, Θ(f(n)) indique une borne supérieure et inférieure du même ordre. Pour une fonction de recherche, précise également le meilleur cas, le cas moyen ou le pire cas : trouver immédiatement le premier élément n’a pas le même nombre d’opérations que parcourir toute la liste.

Temps et mémoire

Une solution peut gagner du temps en conservant des données supplémentaires. Le test de doublons avec Set utilise une mémoire proportionnelle au nombre de valeurs distinctes, alors que la double boucle peut n’utiliser qu’une quantité de mémoire auxiliaire constante. Cette comparaison suppose les performances moyennes usuelles de Set ; la spécification JavaScript exige un accès moyen sous-linéaire, sans imposer une table de hachage précise ni une garantie stricte de O(1).

Mesurer sans tirer de conclusion hâtive

  1. Génère des jeux d’entrée de tailles différentes, par exemple n, 2n et 4n.
  2. Mesure plusieurs exécutions et compare les médianes plutôt qu’un seul résultat.
  3. Utilise les mêmes données, la même version d’exécution et des conditions comparables.
  4. Sépare la préparation des données de la partie mesurée.
  5. Observe aussi la mémoire et les cas défavorables ; une mesure locale ne constitue pas une garantie universelle.

Exercice de vérification

Analyse une boucle qui double son compteur, une double boucle qui compare toutes les paires et une recherche de doublons par Set. Pour chacune, indique la taille d’entrée, le coût temporel, le coût mémoire auxiliaire et les hypothèses. Mesure les trois versions sur des tableaux croissants, puis explique tout écart avec l’analyse théorique.

Critères de réussite

  • La taille d’entrée est définie avant l’analyse.
  • Les boucles sont comptées selon leur nombre réel d’itérations.
  • Temps et mémoire sont distingués.
  • Le cas étudié et les hypothèses sur les structures sont explicités.
  • Le benchmark complète l’analyse, sans être présenté comme une preuve asymptotique.
