2. Frontend

CSS fondamentaux

Maîtriser cascade, héritage, spécificité, unités et modèle de boîte pour produire des styles prévisibles et maintenables.

Tutoriel détailléLot 8 · 2026

Objectifs d’apprentissage

  • Expliquer comment la cascade sélectionne une déclaration.
  • Calculer les grandes différences de spécificité entre sélecteurs.
  • Comprendre contenu, padding, bordure et marge.
  • Choisir des unités adaptées et limiter les valeurs rigides.

1. Relier CSS et HTML

Une règle CSS associe un sélecteur à des déclarations. Une feuille externe est généralement préférable pour les styles partagés : elle sépare contenu et présentation, facilite la réutilisation et permet la mise en cache. Les styles en ligne peuvent être utiles dans certains cas, mais rendent souvent la maintenance et les surcharges plus difficiles.

.carte {
      color: #202124;
      background: white;
      padding: 1rem;
      border-radius: 0.5rem;
    }

Commence par des règles simples et réutilisables. Évite d’ajouter des sélecteurs très longs qui dépendent de la structure exacte de tous les ancêtres.

2. Cascade, héritage et spécificité

Lorsque plusieurs déclarations visent la même propriété, le navigateur applique la cascade : pertinence des règles, origine et importance, couche de cascade, spécificité, proximité de portée si @scope intervient, puis ordre d’apparition. Les animations et transitions suivent aussi des règles de priorité particulières. L’héritage transmet certaines propriétés des parents aux enfants, mais pas toutes.

p { color: #333; }
    .notice { color: #075985; }
    #alerte { color: #b91c1c; }

Dans cet exemple, si le même paragraphe correspond aux trois sélecteurs et que l’origine, l’importance et la couche sont identiques, #alerte gagne : sa spécificité (1, 0, 0) dépasse celle de .notice (0, 1, 0), elle-même supérieure à p (0, 0, 1). Ces valeurs ne s’additionnent pas comme un nombre décimal. Les déclarations importantes et les couches sont évaluées avant la spécificité ; utilise l’inspecteur pour trouver la déclaration gagnante plutôt que d’ajouter des règles au hasard.

3. Modèle de boîte

Chaque boîte CSS comprend le contenu, le remplissage interne (padding), la bordure et la marge externe (margin). Avec le modèle par défaut, la largeur déclarée ne comprend pas nécessairement le remplissage et la bordure. La convention suivante rend souvent les dimensions plus intuitives :

*, *::before, *::after {
      box-sizing: border-box;
    }

Avec border-box, la largeur déclarée inclut le contenu, le padding et la bordure. La marge reste à l’extérieur. Cette règle ne dispense pas de vérifier les contraintes de largeur, les éléments flexibles et les débordements.

4. Unités et dimensions fluides

Les pixels CSS conviennent à certaines bordures ou détails ; rem est utile pour des dimensions liées à la taille de police racine, % dépend du contexte de mise en page, et vw/vh dépendent du viewport. Les unités ne sont pas interchangeables : choisis-les selon le comportement attendu.

.contenu {
      width: min(100% - 2rem, 70rem);
      margin-inline: auto;
    }
    .titre {
      font-size: clamp(1.75rem, 4vw, 3rem);
    }

Utilise min(), max() et clamp() pour exprimer des limites. Évite de verrouiller la hauteur d’un bloc contenant du texte variable, ce qui risque de couper le contenu lorsque le texte est agrandi ou traduit.

5. Organiser les styles

Regroupe les styles par composant ou domaine fonctionnel, adopte une convention de nommage cohérente et limite les exceptions. Les propriétés personnalisées CSS permettent de centraliser des valeurs partagées comme les couleurs et espacements.

:root {
      --couleur-principale: #2457a7;
      --espace: 1rem;
    }
    .bouton-principal {
      background: var(--couleur-principale);
      padding: var(--espace);
    }

Les styles doivent rester compréhensibles lorsqu’un autre développeur doit les modifier. N’utilise pas !important comme méthode générale de résolution des conflits ; identifie la cause dans la cascade et clarifie l’organisation des règles.

Erreurs fréquentes

  • Ajouter des règles répétées sans inspecter la cascade.
  • Confondre largeur du contenu et largeur totale de la boîte.
  • Utiliser des hauteurs fixes pour du texte variable.
  • Employer des unités relatives sans comprendre leur référence.
  • Multiplier les identifiants et les déclarations !important.

Analyse approfondie : diagnostiquer une déclaration CSS

Quand une propriété ne produit pas l’effet attendu, vérifie d’abord si le sélecteur correspond, si la déclaration est valide, si une autre règle la remplace et si la propriété est héritée. Ajouter !important avant d’avoir compris la cascade rend souvent le problème plus difficile à résoudre.

Calcul du modèle de boîte

.carte {
  box-sizing: content-box;
  width: 300px;
  padding: 20px;
  border: 2px solid;
}

Avec content-box, la largeur extérieure vaut ici 300 + 40 + 4 = 344 pixels CSS, sans compter la marge. Avec border-box, les 300 pixels incluent contenu, remplissage et bordure ; la zone de contenu devient donc plus petite. Cette différence explique de nombreux débordements en grille.

Routine de diagnostic

  1. Sélectionne l’élément dans l’inspecteur.
  2. Lis les styles calculés et repère la déclaration gagnante et celles barrées.
  3. Vérifie dimensions, padding, bordure, marge, contraintes min/max et contenu intrinsèque.
  4. Désactive temporairement une règle pour tester une hypothèse, puis applique la correction dans la feuille de style.
  5. Teste le zoom et plusieurs largeurs pour éviter de corriger un cas au prix d’un autre.

Les valeurs personnalisées CSS (--espace) sont héritées et peuvent être redéfinies localement. Donne-leur des noms décrivant leur rôle et vérifie la valeur calculée au point où elles sont utilisées.

Exercice guidé

Crée une carte produit avec titre, description, prix et bouton. Définis des variables CSS pour les couleurs et l’espacement, applique border-box et utilise une largeur maximale. Ajoute une règle volontairement conflictuelle et diagnostique-la dans DevTools.

Critères de réussite

  • La cascade peut être expliquée et les styles sont prévisibles.
  • La boîte conserve les dimensions attendues avec padding et bordure.
  • Le contenu s’adapte à la largeur disponible et au zoom.
  • Les valeurs récurrentes sont centralisées.
  • Aucun correctif global ne masque un débordement non compris.
