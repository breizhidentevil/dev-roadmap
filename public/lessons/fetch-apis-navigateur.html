2. Frontend

Fetch et API navigateur

Effectuer des requêtes HTTP depuis le navigateur, traiter les réponses et gérer les erreurs, l’annulation et les états de chargement.

Tutoriel détailléLot 7 · 2026

Objectifs d’apprentissage

  • Envoyer une requête HTTP avec fetch.
  • Distinguer erreur réseau et réponse HTTP non réussie.
  • Lire et valider le corps d’une réponse.
  • Gérer chargement, erreur, annulation et réponses obsolètes.
  • Comprendre les limites imposées par CORS et les identifiants.

1. Effectuer une requête

fetch renvoie une promesse qui se résout généralement dès que les en-têtes de réponse sont disponibles. La promesse ne rejette pas simplement parce que le serveur renvoie un statut comme 404 ou 500 : il faut vérifier response.ok ou response.status.

async function chargerProduits() {
      const response = await fetch("/api/produits");
      if (!response.ok) {
        throw new Error(`HTTP ${response.status}`);
      }
      return response.json();
    }

response.json() est lui-même asynchrone et peut échouer si le corps n’est pas un JSON valide. Le code appelant doit donc gérer aussi les erreurs de lecture ou de parsing.

2. Envoyer des données JSON

async function creerProduit(produit) {
      const response = await fetch("/api/produits", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(produit)
      });
    
      if (!response.ok) {
        throw new Error(`Création impossible : HTTP ${response.status}`);
      }
      return response.status === 204 ? null : response.json();
    }

Le serveur doit valider les données indépendamment de la validation de formulaire dans le navigateur. Vérifie le contrat de l’API : certaines réponses n’ont pas de corps (par exemple 204), et certaines erreurs utilisent un format JSON documenté. N’assume pas que chaque réponse peut être lue avec json().

3. États de chargement et erreurs

Une interface doit distinguer au minimum chargement, succès vide, succès avec données et échec. Le message utilisateur doit rester compréhensible ; les détails techniques peuvent être journalisés sans exposer d’informations sensibles.

try {
      afficherEtat("chargement");
      const produits = await chargerProduits();
      afficherProduits(produits);
    } catch (erreur) {
      afficherErreur("Impossible de charger les produits.");
      console.error("Chargement des produits échoué", erreur);
    }

Ne transforme pas toutes les erreurs en liste vide : l’utilisateur ne pourrait plus distinguer « aucun résultat » de « service indisponible ». Prévois une action de reprise lorsque cela a du sens.

4. Annuler une requête et éviter les courses

Un changement de page ou de filtre peut rendre une requête inutile. AbortController permet de transmettre un signal à fetch et d’annuler la requête. Lors d’une recherche interactive, évite qu’une réponse ancienne arrive après la plus récente et remplace les résultats actuels.

const controller = new AbortController();
    
    try {
      const response = await fetch("/api/recherche?q=clavier", {
        signal: controller.signal
      });
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      const resultat = await response.json();
    } catch (erreur) {
      if (erreur instanceof DOMException && erreur.name === "AbortError") {
        // Annulation attendue : ne pas afficher une erreur générique.
      } else {
        throw erreur;
      }
    }
    
    // Si la recherche n'est plus utile :
    // controller.abort();

Dans une application réelle, crée un contrôleur par opération annulable et conserve sa référence. Une annulation n’est pas nécessairement une erreur utilisateur.

5. CORS, cookies et sécurité

CORS est un mécanisme appliqué par le navigateur qui contrôle si un script d’une origine peut lire une réponse provenant d’une autre origine. Il doit être configuré sur le serveur qui fournit la ressource ; désactiver la sécurité du navigateur n’est pas une solution acceptable.

Les cookies d’authentification, les options credentials, les politiques SameSite et les protections CSRF doivent être conçus ensemble. N’inclus pas de secrets durables dans le JavaScript livré au navigateur : tout utilisateur peut inspecter ce code. N’envoie pas de jetons ou données personnelles dans les logs.

Erreurs fréquentes

  • Oublier de vérifier response.ok.
  • Supposer que toutes les réponses ont un corps JSON.
  • Confondre erreur réseau, CORS et statut HTTP 4xx/5xx.
  • Afficher une liste vide quand la requête a échoué.
  • Laisser une réponse ancienne écraser les résultats plus récents.
  • Exposer des secrets dans le code client.

Analyse approfondie : réponses obsolètes et validation des données

Une requête peut réussir au niveau HTTP tout en renvoyant un contenu inutilisable pour l’application. Un statut 200 ne prouve ni que le corps est un JSON valide ni qu’il respecte le schéma attendu. Traite les données du réseau comme des entrées non fiables.

Vérifier le contrat minimal

async function chargerTaches(signal) {
  const response = await fetch("/api/taches", { signal });
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  const contenu = await response.json();
  if (!Array.isArray(contenu) ||
      !contenu.every(t => t && typeof t.id === "string" &&
        typeof t.titre === "string")) {
    throw new Error("Format de réponse inattendu");
  }
  return contenu;
}

Adapte la validation au contrat réel : ce contrôle n’est qu’un exemple minimal et ne remplace pas un validateur complet lorsque le schéma est plus complexe. Prévois aussi les réponses sans corps, comme 204 No Content, avant d’appeler response.json().

Éviter qu’une ancienne recherche écrase la nouvelle

Quand une personne tape rapidement, la requête A peut terminer après la requête B. Il faut annuler l’opération précédente et vérifier qu’elle correspond toujours à la recherche courante avant de publier son résultat. L’annulation côté navigateur ne prouve pas que le serveur a interrompu son traitement.

let controleRechercheActif;
let revisionRecherche = 0;

async function rechercher(terme) {
  const revision = ++revisionRecherche;
  controleRechercheActif?.abort();

  const controle = new AbortController();
  controleRechercheActif = controle;

  try {
    const url = `/api/recherche?q=${encodeURIComponent(terme)}`;
    const response = await fetch(url, { signal: controle.signal });
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }

    const resultats = await response.json();

    // Une réponse arrivée en retard ne doit pas remplacer l’état courant.
    if (revision !== revisionRecherche) return;
    afficherResultats(resultats);
  } catch (erreur) {
    // Une annulation attendue ne doit pas devenir un message d’erreur.
    if (controle.signal.aborted) return;
    if (revision === revisionRecherche) {
      afficherErreur("Recherche impossible. Réessayez.");
    }
  } finally {
    // Ne pas effacer le contrôleur d’une recherche plus récente.
    if (controleRechercheActif === controle) {
      controleRechercheActif = undefined;
    }
  }
}

Dans une application réelle, validez également la forme de resultats selon le contrat de l’API avant de l’afficher. Le compteur de révision reste utile même si le transport ne respecte pas immédiatement l’annulation.

Enfin, ne place jamais une clé privée dans le JavaScript livré au navigateur. CORS se configure principalement sur le serveur qui répond et autorise la lecture par une origine ; il ne remplace ni l’authentification ni l’autorisation métier.

Exercice guidé

Crée un composant qui charge une liste depuis une API, affiche un état de chargement, un message d’erreur et un état vide. Ajoute un bouton de nouvelle tentative et une recherche annulable lorsque l’utilisateur change rapidement de terme.

Critères de réussite

  • Les statuts HTTP non réussis sont traités explicitement.
  • Les erreurs de réseau et de parsing ne sont pas confondues avec une réponse vide.
  • L’interface affiche des états compréhensibles.
  • Les requêtes devenues inutiles peuvent être annulées.
  • La configuration CORS reste côté serveur et aucun secret n’est livré au navigateur.
