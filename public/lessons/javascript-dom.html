2. Frontend

Manipulation du DOM en JavaScript

Sélectionner des éléments, construire une interface et synchroniser le DOM avec les actions de l’utilisateur de manière sûre.

Tutoriel détailléLot 7 · 2026

Objectifs d’apprentissage

  • Sélectionner un élément ou une collection du DOM.
  • Créer, modifier, déplacer et supprimer des nœuds.
  • Mettre à jour les classes et attributs sans mélanger contenu et présentation.
  • Afficher du contenu non fiable sans créer de faille XSS.

1. Sélectionner et vérifier les éléments

Le DOM est l’arbre d’objets qui représente le document chargé. querySelector renvoie le premier élément correspondant ou null ; querySelectorAll renvoie une collection statique des correspondances. Il faut donc traiter le cas où un élément n’existe pas, notamment si le script est partagé entre plusieurs pages.

const titre = document.querySelector("h1");
    const cartes = document.querySelectorAll(".carte");
    
    if (titre) titre.textContent = "Catalogue";
    cartes.forEach((carte, index) => {
      carte.setAttribute("data-position", String(index + 1));
    });

Choisis des sélecteurs stables et précis. Si le script s’exécute avant que le HTML concerné soit analysé, déplace le script ou utilise un chargement adapté, par exemple defer sur un script externe.

2. Créer et insérer des éléments

Pour créer du contenu structuré, utilise les API DOM. Construis les éléments, renseigne leurs propriétés, puis insère-les dans le document. Cette approche rend la structure explicite et évite d’interpréter une chaîne comme du HTML.

function creerCarte(nom, description) {
      const article = document.createElement("article");
      article.className = "carte";
    
      const titre = document.createElement("h2");
      titre.textContent = nom;
    
      const texte = document.createElement("p");
      texte.textContent = description;
    
      article.append(titre, texte);
      return article;
    }
    
    document.querySelector("#catalogue")
      ?.append(creerCarte("Clavier", "Modèle compact"));

Pour des listes importantes, prépare les nœuds puis insère-les ensemble avec un fragment ou une opération adaptée. Mesure avant d’optimiser : la lisibilité du code et le volume de données comptent aussi.

3. Modifier classes, attributs et propriétés

Utilise classList pour activer un état visuel, les propriétés DOM pour les valeurs prévues par l’API et setAttribute pour les attributs lorsqu’il est approprié. Pour un panneau repliable, aria-expanded appartient au bouton de commande, tandis que hidden reflète la visibilité de la cible.

<button id="toggle-details" type="button"
        aria-expanded="false" aria-controls="details">
  Afficher les détails
</button>
<section id="details" hidden>Contenu des détails…</section>
const bouton = document.querySelector("#toggle-details");
const panneau = document.querySelector("#details");

if (bouton instanceof HTMLButtonElement &&
    panneau instanceof HTMLElement) {
  bouton.addEventListener("click", () => {
    const ouvrir = bouton.getAttribute("aria-expanded") !== "true";
    bouton.setAttribute("aria-expanded", String(ouvrir));
    panneau.hidden = !ouvrir;
  });
}

Le bouton pilote le comportement au clavier grâce à son élément natif. L’état accessible et la visibilité sont mis à jour dans le même gestionnaire ; aria-controls identifie la cible mais ne crée pas, à lui seul, l’interaction.

4. Sécurité du contenu

textContent affiche une chaîne comme du texte. innerHTML analyse la chaîne comme du balisage, ce qui peut exécuter du contenu malveillant lorsque des données non fiables sont injectées.

const commentaire = document.querySelector("#commentaire");
    const texteUtilisateur = '<img src=x onerror=alert(1)>';
    
    // Sûr pour afficher cette chaîne comme du texte :
    if (commentaire) commentaire.textContent = texteUtilisateur;

Si l’application doit réellement accepter du HTML riche, utilise une stratégie d’assainissement maintenue et adaptée au contexte. N’essaie pas de sécuriser du HTML avec une série de remplacements maison. La validation côté serveur reste nécessaire pour les données métier.

5. Rendu et cycle de vie

Un composant qui crée des nœuds doit aussi prévoir leur mise à jour et leur suppression. Évite d’ajouter plusieurs fois les mêmes éléments lorsque le rendu est relancé. Pour les événements, utilise des écouteurs stables ou la délégation lorsque les éléments sont dynamiques ; retire les écouteurs qui ne sont plus utiles si le cycle de vie l’exige.

Évite les écritures DOM répétées qui forcent inutilement des recalculs de mise en page. Regroupe les lectures de géométrie et les écritures visuelles lorsque la performance est réellement un problème. Mesure le rendu avant d’introduire des optimisations complexes.

Erreurs fréquentes

  • Oublier qu’un sélecteur peut renvoyer null.
  • Utiliser innerHTML pour afficher des saisies utilisateur.
  • Confondre attribut HTML et propriété JavaScript.
  • Créer des doublons lors de rendus successifs.
  • Mettre à jour une classe sans synchroniser l’état accessible correspondant.

Analyse approfondie : événements, formulaires et cycle de vie

Les écouteurs d’événements doivent être attachés au bon élément et leur durée de vie doit correspondre à celle de l’interface. Si un composant est monté plusieurs fois et que ses anciens écouteurs restent actifs, une seule action peut déclencher plusieurs traitements.

Exemple : soumission d’un formulaire

Pour annoncer l’ajout sans déplacer le focus, prévois dès le chargement une région de statut, par exemple <p id="statut" role="status" aria-atomic="true"></p>. Elle doit exister avant que le script mette son texte à jour.

const formulaire = document.querySelector("#ajout-tache");
const champ = document.querySelector("#titre-tache");
const liste = document.querySelector("#taches");
const statut = document.querySelector("#statut");

if (formulaire instanceof HTMLFormElement &&
    champ instanceof HTMLInputElement && liste) {
  formulaire.addEventListener("submit", (event) => {
    event.preventDefault();
    const titre = champ.value.trim();
    if (!titre) {
      champ.focus();
      return;
    }
    const item = document.createElement("li");
    item.textContent = titre;
    liste.append(item);
    if (statut instanceof HTMLElement) {
      statut.textContent = `Tâche ajoutée : ${titre}`;
    }
    formulaire.reset();
    champ.focus();
  });
}

Le formulaire peut être soumis par Entrée, ce qui rend le gestionnaire submit plus approprié qu’un écouteur exclusivement attaché au clic du bouton. Dans une application réelle, ajoute une gestion explicite des erreurs, des libellés et de l’annonce des mises à jour.

Délégation d’événements

Pour une liste qui reçoit souvent de nouveaux éléments, un écouteur sur le conteneur peut traiter les clics descendants via event.target et closest(). Vérifie que la cible trouvée appartient bien au conteneur avant d’agir. La délégation réduit le nombre d’écouteurs, mais ne dispense pas de vérifier le type de l’élément et l’action demandée.

Exercice guidé

Crée une liste de tâches avec un champ texte, un bouton d’ajout et un bouton de suppression par tâche. Construis les nœuds avec createElement, affiche les valeurs avec textContent et utilise une classe CSS pour représenter les tâches terminées.

Critères de réussite

  • Une tâche peut être ajoutée, marquée terminée et supprimée.
  • Une saisie ressemblant à du HTML est affichée comme texte.
  • Les éléments absents et les saisies vides sont traités.
  • Les boutons ont des libellés explicites et sont accessibles au clavier.
  • Les opérations répétées ne créent pas de doublons inattendus.
