2. Frontend

React : composants, props et state

Construire une interface à partir de composants réutilisables, transmettre des données avec les props et gérer l’état local.

Tutoriel détailléLot 8 · 2026

Objectifs d’apprentissage

  • Décomposer une interface en composants cohérents.
  • Écrire un composant fonctionnel en JSX.
  • Transmettre des données avec les props.
  • Choisir entre état local et valeur calculée.

Fil directeur

React transforme une description d’interface en rendu. La séparation en composants doit suivre les responsabilités de l’interface, tandis que les props transportent les entrées et l’état représente les informations qui changent au fil des interactions.

1. Décomposer l’interface par responsabilité

Un composant est une fonction qui reçoit des données et renvoie une description d’interface en JSX. Découpe lorsque des parties ont un rôle identifiable, des données propres ou une réutilisation réelle ; éviter de créer un composant pour chaque ligne sans bénéfice rend le code plus difficile à suivre.

function ProductCard({ product }) {
  return (
    <article>
      <h2>{product.name}</h2>
      <p>{product.price} €</p>
    </article>
  );
}

Le composant décrit le rendu à partir de ses entrées : il ne doit pas modifier directement les données reçues ni effectuer des effets externes pendant le rendu.

2. Transmettre les entrées avec les props

Les props sont les paramètres du composant. Elles permettent au parent de transmettre des valeurs, des callbacks ou du contenu. Traite-les comme des entrées en lecture seule : si une carte doit signaler un clic, elle appelle une fonction fournie plutôt que de modifier elle-même la collection du parent.

function ProductCard({ product, onSelect }) {
  return (
    <button onClick={() => onSelect(product.id)}>
      {product.name}
    </button>
  );
}

Pour les listes, fournis une clé stable issue de l’identité métier. Une clé d’index peut associer un état local au mauvais élément lorsque la liste est réordonnée.

3. Gérer les changements avec un état local

Utilise `useState` pour une information qui évolue et influence le rendu. L’appel retourne la valeur courante et une fonction de mise à jour ; cette fonction planifie un nouveau rendu, elle ne modifie pas la variable dans le code déjà en cours.

const [quantity, setQuantity] = useState(1);

function increase() {
  setQuantity(current => current + 1);
}

La mise à jour fonctionnelle est utile lorsque le prochain état dépend du précédent. Ne stocke pas une valeur calculable à partir des props et de l’état si elle peut être calculée pendant le rendu.

4. Partager l’état au bon niveau

Si deux composants doivent rester synchronisés, place l’état dans leur plus proche parent commun et transmets valeur et actions via props. Ce déplacement est appelé « remonter l’état ». Si la donnée n’est utilisée que localement, la remonter inutilement augmente les dépendances et les rendus à comprendre.

Un rendu doit rester prévisible : à entrées identiques, un composant doit décrire la même interface. Évite les mutations de tableaux et objets existants ; crée une nouvelle valeur avec les changements nécessaires.

5. Donner une identité stable aux éléments d’une liste

type Product = { id: string; name: string; price: number };
type ProductCardProps = {
  product: Product;
  onSelect: (id: string) => void;
};

function ProductCardTyped({ product, onSelect }: ProductCardProps) {
  return (
    <button type="button" onClick={() => onSelect(product.id)}>
      {product.name} — {product.price} €
    </button>
  );
}

// Dans le composant parent :
{products.map(product => (
  <ProductCardTyped
    key={product.id}
    product={product}
    onSelect={onSelect}
  />
))}

La clé key aide React à associer chaque élément rendu à son identité lors des insertions, suppressions et réordonnancements. Elle doit être stable et unique parmi les frères ; elle n’est pas transmise comme une prop ordinaire au composant. Évite les clés aléatoires générées à chaque rendu et les index si la liste peut changer d’ordre. Le type des props rend aussi le contrat du composant explicite, mais ne valide pas les données reçues d’une API à l’exécution.

Erreurs fréquentes et diagnostic

  • Modifier directement une prop ou un objet d’état.
  • Utiliser un index de tableau comme clé pour une liste réordonnable.
  • Créer un état pour une valeur qui peut être calculée.
  • Déplacer tout l’état à la racine sans besoin partagé.
  • Effectuer une requête ou modifier le DOM directement pendant le rendu.

Exercice guidé

Construis une liste de produits avec une carte réutilisable, un bouton de sélection et un compteur de quantité. Fais porter la sélection par le parent si plusieurs composants doivent l’utiliser. Ajoute, retire et réordonne des éléments pour vérifier les clés et l’immuabilité.

Critères de réussite

  • Chaque composant a une responsabilité identifiable.
  • Les props sont traitées comme des données en lecture seule.
  • Les changements d’état déclenchent le rendu attendu.
  • Les listes utilisent des clés stables.
  • L’état est placé au niveau minimal qui permet le partage nécessaire.
