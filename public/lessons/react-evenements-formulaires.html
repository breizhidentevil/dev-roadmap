2. Frontend

React : événements et formulaires

Gérer les interactions, les champs contrôlés, la validation et la soumission de formulaires.

Tutoriel détailléLot 8 · 2026

Objectifs d’apprentissage

  • Relier un gestionnaire à une interaction.
  • Gérer les champs contrôlés avec l’état.
  • Valider et présenter les erreurs clairement.
  • Soumettre sans rechargement non désiré.

Fil directeur

Un formulaire React relie une interaction utilisateur à un état, puis à une validation et à une action explicite. Une bonne implémentation garde les données compréhensibles, expose les erreurs près des champs et reste utilisable au clavier.

1. Relier les événements à une intention

Les gestionnaires d’événements sont transmis à React, par exemple `onClick` ou `onSubmit`. Passe une fonction, pas le résultat de son exécution. Place les changements d’état dans le gestionnaire qui correspond à l’action utilisateur ; ne déclenche pas une action métier pendant le rendu.

<button type="button" onClick={handleAdd}>Ajouter</button>

Précise le type des boutons dans un formulaire : sans `type="button"`, un bouton peut soumettre le formulaire par défaut.

2. Choisir un modèle de champ cohérent

Un champ contrôlé reçoit sa valeur depuis l’état React et met à jour cet état dans `onChange`. Le champ non contrôlé conserve plutôt sa valeur dans le DOM, avec `defaultValue` ou une référence. Choisis le modèle en fonction du besoin ; éviter de basculer entre valeur définie et `undefined` pendant la vie du champ.

const [email, setEmail] = useState("");
<label htmlFor="email">Adresse e-mail</label>
<input
  id="email"
  type="email"
  value={email}
  onChange={event => setEmail(event.target.value)}
/>

Le contrôle donne une source de vérité claire, mais chaque changement provoque une mise à jour d’état. Pour les formulaires très simples, un modèle non contrôlé peut suffire.

3. Valider avant l’action asynchrone

À la soumission, empêche le rechargement natif si l’application prend en charge la soumission, puis valide les données. La validation HTML (`required`, `type`, `minLength`) améliore l’expérience, mais ne remplace jamais la validation côté serveur. Traite séparément les erreurs de champ, les erreurs globales et les erreurs réseau.

function handleSubmit(event) {
  event.preventDefault();
  if (!email.trim()) {
    setError("L’adresse e-mail est obligatoire.");
    return;
  }
  setError("");
  // Envoyer ensuite les données validées au serveur.
}

Pour un envoi asynchrone, indique l’état de chargement, empêche les doubles soumissions si nécessaire et rétablis l’interface en cas d’échec.

4. Rendre le résultat accessible

Associe chaque champ à un `label` explicite. Relie les messages d’erreur au champ avec `aria-describedby` et indique un état invalide avec `aria-invalid` lorsque c’est pertinent. Ne communique pas une erreur uniquement par la couleur. Après un échec, place le focus de façon utile ou annonce le message global sans déplacer arbitrairement l’utilisateur.

Le serveur reste l’autorité pour les règles métier et les autorisations ; le navigateur ne doit pas être considéré comme une frontière de sécurité.

Erreurs fréquentes et diagnostic

  • Oublier `event.preventDefault()` lorsque la soumission est gérée côté client.
  • Utiliser un bouton de soumission pour une action secondaire.
  • Afficher une erreur uniquement par une couleur.
  • Considérer la validation client comme une protection serveur.
  • Ne pas gérer chargement, échec ou double soumission.

Exercice guidé

Crée un formulaire de contact avec nom, e-mail et message. Implémente des champs contrôlés, une validation claire, un état de soumission, un message d’échec simulé et un message de succès. Vérifie l’usage clavier et l’association des erreurs aux champs.

Critères de réussite

  • Chaque champ a un libellé explicite.
  • La soumission est gérée une seule fois et les erreurs sont compréhensibles.
  • Les états chargement, échec et succès sont visibles.
  • Les champs et messages restent utilisables au clavier et avec un lecteur d’écran.
  • La validation serveur est considérée comme obligatoire pour les règles métier.
