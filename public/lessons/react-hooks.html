2. Frontend

React Hooks

Utiliser les Hooks pour gérer l’état, les effets et les références en respectant les règles de React.

Tutoriel détailléLot 8 · 2026

Objectifs d’apprentissage

  • Appliquer les règles d’appel des Hooks.
  • Distinguer état, effet et référence.
  • Éviter les effets superflus et les dépendances incorrectes.
  • Extraire une logique réutilisable.

Fil directeur

Les Hooks permettent à un composant fonctionnel de conserver un état et de synchroniser son cycle de vie avec des systèmes externes. Ils ne sont pas des fonctions à appeler librement : leur ordre doit rester stable entre les rendus.

1. Respecter les règles des Hooks

Appelle les Hooks au niveau supérieur d’un composant React ou d’un Hook personnalisé, avant tout retour conditionnel. Ne les appelle pas dans une boucle, une condition ou une fonction imbriquée : React associe l’état à l’ordre des appels. Les Hooks personnalisés commencent par `use` et composent d’autres Hooks pour partager une logique, pas un état global automatiquement.

2. Utiliser useState pour l’état rendu

`useState` convient aux informations qui changent et modifient l’interface. La valeur renvoyée correspond au rendu courant ; appeler le setter planifie le suivant. Quand la mise à jour dépend de la valeur précédente, utilise une fonction de mise à jour pour éviter de travailler sur une capture ancienne.

setCount(current => current + 1);

Si une valeur peut être dérivée des props et de l’état, calcule-la au lieu de la dupliquer dans un second état synchronisé.

3. Réserver useEffect à la synchronisation externe

Un effet sert à synchroniser le composant avec quelque chose qui vit hors de React : abonnement, minuterie, connexion ou API impérative. Son cycle comprend installation et, si nécessaire, nettoyage avant une nouvelle installation ou au démontage. Les dépendances doivent représenter toutes les valeurs réactives utilisées dans l’effet.

useEffect(() => {
  const controller = new AbortController();
  void loadData(resourceId, { signal: controller.signal }).catch(error => {
    if (error.name !== "AbortError") console.error(error);
  });
  return () => controller.abort();
}, [resourceId]);

Ce motif transmet explicitement `resourceId` à la requête et annule la requête précédente lorsque l’identifiant change ou que le composant est démonté. `loadData` doit accepter et traiter le signal ; l’exemple ignore `AbortError` et journalise les autres erreurs, mais une interface réelle devrait aussi exposer un état d’erreur adapté. N’utilise pas un effet pour recalculer simplement une valeur que le rendu peut produire.

4. Employer useRef et les Hooks personnalisés

`useRef` conserve une valeur entre les rendus sans déclencher de nouveau rendu lorsqu’elle change. Il convient notamment pour référencer un élément DOM ou garder un identifiant de minuterie. Si la valeur doit apparaître à l’écran, un état est généralement plus approprié.

Un Hook personnalisé peut encapsuler un abonnement ou une logique de chargement. Il doit avoir un contrat clair, nettoyer les ressources et exposer les états utiles sans cacher des comportements surprenants.

Erreurs fréquentes et diagnostic

  • Appeler un Hook dans une condition ou après un retour conditionnel.
  • Omettre une dépendance réactive d’un effet.
  • Employer useEffect pour calculer une valeur dérivée.
  • Créer une souscription sans nettoyage.
  • Mettre dans une ref une valeur qui doit déclencher un rendu.

Exercice guidé

Crée un Hook `useWindowWidth` qui s’abonne au redimensionnement et retire l’écouteur au nettoyage. Puis crée un composant de chargement par identifiant qui annule la requête précédente. Vérifie les changements d’identifiant et le démontage.

Critères de réussite

  • Les Hooks sont appelés au niveau supérieur.
  • Les dépendances reflètent les valeurs réellement utilisées.
  • Chaque abonnement ou ressource externe est nettoyé.
  • L’état et les refs sont employés selon leur effet sur le rendu.
  • Le Hook personnalisé a un contrat documenté et des tests de cas limites.
