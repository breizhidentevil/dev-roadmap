2. Frontend

Responsive design

Concevoir des interfaces qui s’adaptent au contenu, à la fenêtre, aux préférences d’affichage et aux différents modes d’interaction.

Tutoriel détailléLot 7 · 2026

Objectifs d’apprentissage

  • Différencier une mise en page fluide d’une mise en page adaptative.
  • Utiliser des unités relatives, des contraintes de largeur et des media queries.
  • Choisir les points de rupture à partir du contenu.
  • Tester le zoom, l’orientation et les préférences de l’utilisateur.

1. Penser en contraintes plutôt qu’en appareils

Le responsive design vise à préserver l’accès au contenu et aux fonctionnalités lorsque l’espace disponible ou le mode d’interaction change. Il ne s’agit pas de reproduire un modèle de téléphone précis, mais de faire en sorte que la mise en page réagisse à ses contraintes. Une grille fluide, des images flexibles et des composants capables de se réorganiser sont généralement plus robustes qu’une collection de tailles fixes.

Commence par une structure simple qui fonctionne sur une petite largeur, puis élargis progressivement. Observe à quel moment le contenu devient trop serré : ce point, plutôt qu’une liste de modèles d’appareils, est un bon candidat pour un point de rupture.

2. Préparer le viewport et les dimensions

Sur une page HTML destinée aux appareils mobiles, indique le viewport pour que la largeur CSS corresponde à la largeur de l’appareil.

<meta name="viewport" content="width=device-width, initial-scale=1">

Préfère des limites souples : width: 100%, max-width, min(), max() et clamp(). Par exemple, un conteneur peut occuper la largeur disponible tout en restant limité sur un grand écran.

.contenu {
      width: min(100% - 2rem, 72rem);
      margin-inline: auto;
    }
    h1 { font-size: clamp(1.8rem, 4vw, 3.5rem); }
    img, video { max-width: 100%; height: auto; }

3. Media queries et points de rupture

Les media queries permettent d’appliquer des règles selon les caractéristiques du support, notamment la largeur de viewport, l’orientation ou les préférences utilisateur. Utilise-les lorsque le contenu a besoin d’une autre disposition, pas pour chaque appareil rencontré.

.layout {
      display: grid;
      grid-template-columns: 1fr;
      gap: 1rem;
    }
    @media (min-width: 48rem) {
      .layout { grid-template-columns: 16rem minmax(0, 1fr); }
    }

Les seuils dépendent de la typographie, des libellés et du contenu réel. Vérifie aussi le comportement juste avant et juste après chaque seuil : les défauts de responsive apparaissent souvent à ces largeurs intermédiaires.

4. Toucher, clavier et préférences

Une interface responsive doit aussi rester utilisable avec des modes d’interaction différents. Les zones interactives doivent être suffisamment grandes et espacées, sans dépendre uniquement du survol. Conserve un focus visible au clavier. Si une animation n’est pas indispensable, respecte la préférence de réduction des mouvements.

@media (prefers-reduced-motion: reduce) {
      *, *::before, *::after {
        scroll-behavior: auto !important;
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
      }
    }

Adapte cette règle avec discernement : certaines animations transmettent une information. La durée très courte et une seule itération évitent notamment qu’une animation infinie continue de tourner. Pour un mouvement non essentiel, supprimer entièrement l’animation peut être préférable ; vérifie que le changement d’état reste compréhensible sans mouvement.

5. Tester le responsive

Teste plusieurs largeurs, l’agrandissement du texte, le zoom, l’orientation et les contenus longs. Le simulateur du navigateur est utile, mais ne reproduit pas toutes les caractéristiques d’un appareil réel. Vérifie les formulaires, les menus, les tableaux, les images et les composants qui affichent des données variables.

Un défilement horizontal peut être légitime pour un tableau de données ou un éditeur, mais il ne devrait pas être nécessaire pour lire le texte courant. N’utilise pas overflow-x: hidden comme correctif universel : identifie d’abord l’élément responsable du débordement.

Erreurs fréquentes

  • Choisir des points de rupture uniquement selon des modèles d’appareils.
  • Fixer la largeur et la hauteur de tous les composants.
  • Oublier les textes longs, les traductions et les zooms.
  • Supprimer les indicateurs de focus ou dépendre du survol.
  • Masquer le débordement au lieu d’en comprendre la cause.

Analyse approfondie : valider les vrais cas limites

Le responsive ne se résume pas à vérifier une largeur de téléphone et une largeur d’ordinateur. Les défauts apparaissent souvent entre les points de rupture, avec des traductions longues, un zoom important, une barre de navigation ouverte ou une police différente.

Protocole de test

  1. Teste les largeurs juste en dessous, au niveau et juste au-dessus de chaque media query.
  2. Vérifie le zoom navigateur et l’agrandissement du texte, sans supposer que le zoom équivaut à un viewport mobile.
  3. Contrôle les tableaux, menus, formulaires et dialogues : chacun peut avoir des contraintes différentes.
  4. Vérifie les images, vidéos et contenus embarqués, ainsi que les chaînes longues sans espace.
  5. Contrôle le focus clavier après la réorganisation et l’orientation portrait/paysage.

Respecter les préférences utilisateur

@media (prefers-reduced-motion: reduce) {
  .animation-longue {
    animation-duration: 0.01ms;
    animation-iteration-count: 1;
  }
}

Cette règle est une illustration : selon l’animation, il peut être préférable de supprimer complètement le mouvement plutôt que d’en réduire la durée. Le principe est de ne pas imposer une animation non essentielle aux personnes qui demandent une réduction des mouvements. Pense aussi au contraste en mode sombre, au contenu quand les polices système sont agrandies et aux zones tactiles suffisamment espacées.

Exercice guidé

Transforme une page de catalogue à trois colonnes en une mise en page fluide. Ajoute une barre de navigation qui peut se réorganiser, limite la largeur du texte et adapte les tailles de titre avec clamp(). Teste à plusieurs largeurs ainsi qu’avec un zoom élevé.

Critères de réussite

  • Le contenu principal ne nécessite pas de défilement horizontal involontaire.
  • Les points de rupture correspondent à un besoin observable du contenu.
  • Les images et cartes restent dans leur conteneur.
  • Les actions sont utilisables au clavier et au toucher.
  • Le texte reste lisible quand il est agrandi.
