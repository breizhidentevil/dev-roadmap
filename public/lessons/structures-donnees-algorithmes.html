Structures de données et algorithmes

Choisir une représentation adaptée aux opérations attendues et construire des traitements corrects, lisibles et testables.

Tutoriel détailléLot 5 · 2026

Objectifs d’apprentissage

  • Associer une structure de données à un besoin précis.
  • Utiliser tableaux, objets, Map, Set, piles et files.
  • Décrire la recherche, le tri et le parcours d’une structure.
  • Tester les cas limites et comparer les coûts des opérations.

1. La structure découle des opérations

Une structure de données organise les valeurs afin de rendre certaines opérations simples. Avant de choisir, liste les actions dominantes : accéder par indice, rechercher par clé, vérifier l’unicité, ajouter au début, traiter dans l’ordre d’arrivée ou explorer des relations.

2. Tableaux, Map et Set

const commandes = [
      { id: "c1", total: 25 },
      { id: "c2", total: 40 },
      { id: "c3", total: 25 }
    ];
    
    const total = commandes.reduce((s, c) => s + c.total, 0);
    const parId = new Map(commandes.map(c => [c.id, c]));
    const totauxUniques = new Set(commandes.map(c => c.total));
    
    console.log(total); // 90
    console.log(parId.get("c2")); // { id: "c2", total: 40 }
    console.log(totauxUniques.size); // 2

find renvoie le premier élément correspondant, filter construit une nouvelle liste filtrée, map transforme chaque élément et reduce agrège. Choisis la méthode qui exprime l’intention ; n’utilise pas reduce uniquement parce qu’il peut tout faire.

// Pile : historique de navigation simplifié
    const pile = [];
    pile.push("/accueil");
    pile.push("/profil");
    const retour = pile.pop(); // "/profil"
    
    // File : traitement dans l’ordre d’arrivée
    const file = ["tache-1", "tache-2", "tache-3"];
    let tete = 0;
    while (tete < file.length) {
      traiter(file[tete]);
      tete += 1;
    }
    function traiter(tache) { console.log(tache); }

Pour une file volumineuse, avancer un indice évite de décaler tous les éléments à chaque suppression. Dans un vrai service, il faut aussi définir les limites de taille, la gestion des erreurs et le comportement en cas de surcharge.

4. Recherche et tri

Une recherche linéaire inspecte les éléments un à un. Une recherche binaire peut réduire fortement le nombre de comparaisons, mais exige des données déjà triées et un ordre cohérent.

function rechercheBinaire(tab, cible) {
      let gauche = 0, droite = tab.length - 1;
      while (gauche <= droite) {
        const milieu = Math.floor((gauche + droite) / 2);
        if (tab[milieu] === cible) return milieu;
        if (tab[milieu] < cible) gauche = milieu + 1;
        else droite = milieu - 1;
      }
      return -1;
    }
    console.log(rechercheBinaire([2, 5, 8, 12, 17], 12)); // 3

JavaScript permet de trier avec sort, mais pour des nombres il faut fournir un comparateur : nombres.sort((a, b) => a - b). Sans comparateur, les valeurs sont comparées comme des chaînes. Vérifie aussi si le tri modifie le tableau original.

5. Graphes et invariants

const graphe = new Map([
      ["A", ["B", "C"]],
      ["B", ["D"]],
      ["C", ["D"]],
      ["D", []]
    ]);
    
    function parcoursLargeur(depart) {
      const visites = new Set([depart]);
      const file = [depart];
      for (let i = 0; i < file.length; i++) {
        const sommet = file[i];
        console.log(sommet);
        for (const voisin of graphe.get(sommet) ?? []) {
          if (!visites.has(voisin)) {
            visites.add(voisin);
            file.push(voisin);
          }
        }
      }
    }

Le parcours en largeur explore les voisins par distance croissante dans un graphe non pondéré. Le Set des sommets visités empêche de boucler indéfiniment en présence de cycles. Dans tout algorithme, identifie les invariants : ce qui doit rester vrai à chaque étape.

Erreurs fréquentes

  • Choisir une structure sans considérer les opérations réellement fréquentes.
  • Oublier les tableaux vides, les doublons et les éléments absents.
  • Utiliser la recherche binaire sur une liste non triée.
  • Muter un tableau partagé sans le signaler.
  • Oublier l’ensemble des sommets visités dans un graphe cyclique.

Exercice

À partir d’une liste de commandes, calcule le total, regroupe les commandes par client avec une Map, puis repère les clients uniques. Ajoute une recherche par identifiant et teste identifiant absent, liste vide et doublons.

Critères de réussite

  • Chaque structure répond à un besoin explicite.
  • Les résultats sont corrects sur cas normal et cas limites.
  • Les fonctions ont une responsabilité claire.
  • Le coût des opérations principales peut être expliqué.

Approfondissement — choisir une structure à partir d’un scénario concret

La bonne structure dépend des opérations dominantes, du volume et des invariants métier. Une liste de commandes doit souvent conserver un ordre, tandis qu’un index par identifiant doit répondre rapidement à des recherches répétées. Il est courant de conserver les deux représentations lorsque les usages le justifient, à condition de maintenir leur cohérence.

const commandes = [
  { id: "c-1", clientId: "u-7", total: 30 },
  { id: "c-2", clientId: "u-2", total: 45 },
  { id: "c-3", clientId: "u-7", total: 12 }
];

const parId = new Map(commandes.map(c => [c.id, c]));
const parClient = new Map();
for (const commande of commandes) {
  const liste = parClient.get(commande.clientId) ?? [];
  liste.push(commande);
  parClient.set(commande.clientId, liste);
}

console.log(parId.get("c-2")?.total); // 45
console.log(parClient.get("u-7")?.length); // 2

Le tableau reste adapté à l’affichage et au parcours séquentiel ; la Map fournit un index explicite par clé ; la seconde Map regroupe plusieurs commandes par client. Ce sont des vues dérivées : si une commande change de client, il faut mettre à jour les index ou les reconstruire. Construire une Map directement à partir d’entrées avec des identifiants dupliqués conserve une seule valeur par clé, généralement la dernière : vérifie l’unicité avant de choisir cette stratégie.

Invariant et preuve informelle

Dans un parcours de graphe en largeur, l’invariant utile est : tout sommet ajouté à la file est déjà marqué comme visité. Marquer au moment de l’ajout évite que deux voisins n’ajoutent le même sommet avant son traitement. Pour un graphe représenté par listes d’adjacence, le coût du parcours est en général O(V + E), où V désigne le nombre de sommets et E le nombre d’arêtes examinées.

function parcoursLargeur(graphe, depart) {
  const visites = new Set([depart]);
  const file = [depart];
  for (let i = 0; i < file.length; i++) {
    const sommet = file[i];
    for (const voisin of graphe.get(sommet) ?? []) {
      if (!visites.has(voisin)) {
        visites.add(voisin); // avant l'ajout à la file
        file.push(voisin);
      }
    }
  }
  return visites;
}

Cette fonction renvoie l’ensemble des sommets atteignables depuis le départ, pas un plus court chemin lui-même. Pour reconstruire un chemin, il faut mémoriser le prédécesseur de chaque sommet découvert. Si le graphe est pondéré, le parcours en largeur ne garantit pas le chemin de coût minimal ; il faut un algorithme adapté aux poids.

Exercice de vérification

Construis un index par identifiant et un regroupement par client pour 10 000 commandes. Décide ce qui doit arriver si deux commandes partagent le même identifiant. Ajoute ensuite un graphe avec un cycle et un sommet isolé, puis vérifie quels sommets sont atteignables depuis un départ donné.

Critères de réussite

  • Chaque structure est justifiée par les opérations attendues.
  • Les identifiants dupliqués ont un comportement explicite.
  • Le parcours termine en présence d’un cycle.
  • La complexité annoncée précise ses hypothèses et distingue sommets et arêtes.
  • La solution ne confond pas parcours en largeur et plus court chemin pondéré.
